# 3D 耳模型工程分析桌面软件：第一版设计

**状态：已批准，待实施计划**
**日期：2026-07-15**

## 1. 目标与范围

将当前 Python 3D 耳模型分析主线封装为仅在 Windows 10/11 本机运行的中文工程软件。软件交付为用户可双击安装/启动的应用，不要求用户单独配置 Python 环境。

第一版必须完整覆盖当前分析能力：输入标准化、W2 patch-based remesh、raw/repaired/salvaged QC、整耳 Weld repair、GPA 与可选固定参考耳对齐、PCA/平均耳，以及现有 CSV、PLY、OBJ、STL、PNG、manifest、日志的查看和导出。

第一版不包含：中英文切换、region table/边界控制点编辑、距离/面积/角度量测、PDF/Word 报告、网络协作、多人并发或云端运行。

## 2. 约束与成功标准

- 技术栈：PySide6（桌面壳与界面）+ PyVista/VTK（模型浏览）+ 现有 Python 分析模块。
- 算法一致性优先：GUI 不重新实现任何 remesh、Weld、对齐或 PCA 算法，只通过受控运行协议调用现有分析核心。
- 每次正式分析均使用独立、空的 `--output-root`，不得写入 legacy 共享 `output/`。
- 对相同输入和参数，桌面端的 manifest、状态汇总和分析产物必须与 CLI 基线一致。
- 每一个被拦截的样本或区域都必须在界面显示其阶段、原因与可打开的证据。

## 3. 系统架构

```text
PySide6 主窗口
  ├─ UI 页面：项目、导入校验、配置、运行、结果、专家模式、运行记录
  ├─ Application Services
  │    ├─ ProjectService        项目、输入副本与配置快照
  │    ├─ ValidationService     导入前检查与用户可读错误
  │    ├─ RunController         子进程、事件、暂停/取消/恢复
  │    ├─ ArtifactIndexer       manifest/CSV/图像/网格索引
  │    └─ ResultService         门禁链与失败证据模型
  ├─ MeshViewer（PyVista/VTK） 3D 图层、视角、Region/QC 高亮
  └─ 现有分析核心（受控子进程）
       scripts/run_full_pipeline.py 与既有阶段脚本
       ear_param/*
```

桌面代码置于新的 `desktop_app/` 包中，不向 `ear_param/` 引入 Qt、VTK 或 GUI 状态。现有核心仅增加必要的、可被 CLI 和 GUI 共用的运行协议：结构化事件、检查点状态与阶段恢复接口；这些适配不得改变数学计算或已有 CLI 默认行为。

## 4. 项目与运行目录

用户创建项目时选择一个独立工作目录。软件将导入数据复制到项目内，原始来源路径只记录为来源信息，不作为分析过程中的可变依赖。

```text
<project-root>/
  project.json                    # 项目元数据、当前配置选择、应用版本
  inputs/
    clean_mesh/                   # 已复制的 PLY
    landmarks/                    # 已复制的 landmark CSV
    config/                       # region table 与 edge controls 快照
  runs/
    <run-id>/
      desktop_state.json          # UI 任务状态、检查点和恢复信息
      events.jsonl                # GUI 消费的结构化进度事件
      artifacts/                  # 唯一 --output-root；由核心创建与写入
        .pipeline-reservation
        manifest.json
        pipeline_run_summary.csv
        pipeline_batch_summary.csv
        ...全部中间层与结果...
```

`artifacts/` 启动时必须不存在或为空，由分析核心原子认领；`desktop_state.json` 与 `events.jsonl` 位于其父目录，避免破坏现有 `prepare_empty_output_root()` 约束。每次运行的配置、输入文件元数据、软件版本和代码状态均由 manifest 与项目状态共同记录。

## 5. 默认交互流程

### 5.1 引导式流程

1. **新建项目**：设置名称和空的项目工作目录。
2. **导入数据**：选择 mesh 目录、landmark 目录和现有配置文件，软件复制输入并显示清单。
3. **自动校验**：检查文件配对、重复标签、CSV 必需列、region table 字段、配置可读性和目标目录可写性。存在阻断错误时不能进入运行。
4. **运行配置**：选择全量或指定样本、是否生成 remesh QC、salvage 阈值、PCA 方差阈值、可选固定参考耳。只显示已批准的少量参数；配置文件内容不在 GUI 编辑。
5. **一键全流程分析**：启动隔离运行，依次执行规范化、W2、QC、Weld、对齐和 PCA。
6. **结果复核与导出**：查看状态、模型与证据，打开或复制既有产物。

### 5.2 专家模式

专家模式允许对当前项目的既有运行重跑 W2、Remesh QC、Weld、对齐或 PCA。界面只呈现前置输入层已满足的阶段，并为每一次专家操作建立新的独立运行记录；不得覆盖原运行或绕过 QC 门禁。

## 6. 主要页面

| 页面 | 目的 | 关键内容 |
|---|---|---|
| 项目首页 | 创建、打开、定位项目 | 最近项目、项目路径、最近运行状态 |
| 导入与校验 | 建立可信输入 | 文件配对表、阻断错误、警告、配置快照 |
| 运行配置 | 组装本次分析参数 | 样本范围、QC 开关、阈值、参考耳、运行前摘要 |
| 运行监控 | 观察和控制任务 | 当前阶段/样本、事件时间线、日志、暂停、取消 |
| 结果工作台 | 复核分析结果 | 三栏工作站、模型图层、样本/区域状态、检查器、证据入口 |
| 专家模式 | 按阶段重跑 | 可用阶段、输入契约、参数、运行原因 |
| 运行记录 | 追溯和恢复 | 状态、开始/结束时间、manifest、日志、恢复入口 |

界面为中文；技术名词如 Raw、Repaired、Salvaged、Weld、GPA、PCA 可保留英文，并始终配套中文释义或阶段说明。

## 7. 结果工作台与 3D 查看

结果工作台采用固定的工程工作站结构：

- 左侧：项目和工作区导航。
- 中间：主 3D 视图、图层栏与样本选择条。
- 右侧：检查器，展示当前样本/区域/图层的门禁链、状态、失败原因和证据操作。

模型查看必须支持旋转、缩放、平移和复位视图；支持 raw、repaired、salvaged、整耳和平均耳切换；支持 Region 与 QC 问题高亮。界面不提供量测工具。不可用图层必须置灰，说明其缺失是由上游状态或产物缺失造成。

选择样本或区域后，检查器按以下顺序展示：输入发现、raw QC、salvage、Weld、对齐、PCA 纳入状态。对失败或拦截项，显示机器原始原因、中文解释、关联 region/共享边和可以打开的 QC PNG、CSV 或日志。

## 8. 运行状态、暂停、取消与恢复

一次只允许一个本地运行。状态机为：

```text
CREATED -> VALIDATING -> QUEUED -> RUNNING -> PAUSE_REQUESTED -> PAUSED
                                         |                         |
                                         v                         v
                                     CANCELLED <-------------- RESUMING
                                         |
                                         v
                                   COMPLETED / FAILED
```

- **暂停**：是协作式安全暂停。控制器记录请求，当前原子处理单元完成后停止后续调度；只有 manifest/阶段产物通过检查时才转为 `PAUSED`。
- **取消**：停止受控子进程，状态标为 `CANCELLED`。已写入的证据被保留，但未完成阶段和未验证产物不被索引为可用结果。
- **失败**：保留异常、退出码、事件、最后安全检查点与可恢复条件，状态标为 `FAILED`。
- **恢复**：读取 `desktop_state.json`、manifest 和产物，验证最近成功阶段的输入/输出契约后继续。若验证失败，只提供从更早阶段重跑，不能假装续跑成功。

对于第一版，暂停并不承诺在任意 Python 指令中即时冻结；它明确发生在分析核心声明的安全检查点。取消可以即时请求，但仍需在隔离目录中将结果标记为不可用于下游分析。

## 9. 数据与接口契约

- 正式全流程运行调用 `scripts/run_full_pipeline.py`，显式传入项目内输入目录、配置快照和 `runs/<run-id>/artifacts`。
- GUI 进度以 JSONL 事件为主；终端输出、`pipeline_run.log` 仅作为人类可读补充。
- ArtifactIndexer 以 `manifest.json` 为运行根证据，结合阶段汇总 CSV、QC 汇总和文件存在性建立索引；不能只因文件名存在就将产物认定为有效。
- ResultService 使用现有严格门禁：raw/salvaged/Weld/对齐/PCA 的状态都来自核心产物，且不允许 GUI 放宽阈值或绕过 `pca_ready`。
- CLI compatibility：未传 GUI 专用参数时，既有脚本保持其当前输入、输出和行为；GUI 专用适配必须通过独立测试覆盖。

## 10. 错误表达

| 类型 | 表达与处理 |
|---|---|
| 输入错误 | 阻断运行；列出文件、字段/配对错误与修复建议。 |
| QC 拦截 | 作为有效分析结论显示；给出阶段、样本/区域、原因与证据入口。 |
| 运行错误 | 记录异常、退出码、日志和最后检查点；提供受约束的恢复/重跑。 |
| 产物读取错误 | 标记运行完整性失败，不提供下游使用；可重新索引或从安全阶段重跑。 |

## 11. 测试与验收

1. **核心回归**：现有 Python 测试持续通过。
2. **契约测试**：项目创建、输入复制、空 output-root、manifest、事件、状态迁移和恢复验证。
3. **CLI 一致性测试**：固定小型样本集、相同参数下，GUI/CLI 的 manifest 参数、汇总表、状态和关键模型/CSV 哈希一致。
4. **运行控制测试**：暂停、取消、异常、恢复、重复运行和非空输出目录拒绝均有自动化覆盖。
5. **界面集成测试**：向导不能跳过阻断校验；选择失败项能定位证据；3D 图层与检查器同步；不可用图层不会伪装为成功。
6. **Windows 交付测试**：在干净的 Windows 10/11 环境中完成安装、启动、项目创建、一次小样本运行和结果浏览。

第一版验收以“相同输入和参数下结果与 CLI 一致，且每一个拦截对象可解释、可追溯”为核心，而非仅以界面可打开为准。

## 12. 实施阶段

1. 运行协议与核心测试：事件、检查点、恢复契约，保持 CLI 兼容。
2. 桌面工程骨架：依赖、打包配置、数据模型、项目和输入服务。
3. 默认向导与运行控制：校验、配置、全流程启动、事件和状态机。
4. 产物索引与结果工作台：manifest/CSV/QC 读取、门禁解释、文件打开。
5. PyVista/VTK 查看器：图层加载、视角控制、Region/QC 高亮。
6. 专家模式与恢复：阶段重跑、暂停/取消/恢复的完整 UI 和契约。
7. 一致性回归、Windows 打包与验收。
