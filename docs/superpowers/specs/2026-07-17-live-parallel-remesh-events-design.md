# 并行 Remesh 实时进度事件设计

## 目标

让桌面端在并行 Remesh/QC 运行期间实时显示每个样本、每个 region 的进度，而不是等一个样本完整结束后再一次性显示。

## 设计

并行子进程仍只写各自私有 JSONL 事件文件，绝不并发写主 `events.jsonl`。管线协调线程在等待工作线程完成时，以短轮询周期增量读取每个私有文件；每份文件维护独立字节偏移量，只转发完整 JSON 行，并由协调线程调用已有 `event_reporter` 写入主事件流。

完成时保留现有“补读至 EOF”逻辑，确保最后一批事件不会遗漏。事件转发将使用原始事件时间戳和字段；主事件流只有协调线程写入，UI 既有 500 ms 轮询无需修改即可实时更新。

## 边界与验收

- 仅并行模式使用私有事件日志与增量转发；串行 CLI 继续直接写主 event log。
- 私有日志不存在、暂时为空或包含未写完的最后一行时，不应中断分析或重复转发。
- 单个 region 事件写入私有文件后，在工作单元尚未结束时即可在 `event_reporter` 中观察到。
- 样本完成后不会重复转发已显示的 region 事件。
